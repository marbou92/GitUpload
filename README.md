# GitUpload

> Upload whole folders and multiple files to your GitHub repositories in a
> single atomic commit — directly from your Android device.

GitUpload is an Android application that turns your phone into a powerful
GitHub productivity tool. Instead of uploading files one at a time through
the GitHub web UI, GitUpload stages an entire folder (or a hand-picked set
of files) and pushes them to any branch of any of your repositories as **one
atomic Git commit** — built on top of the [Git Database
API](https://docs.github.com/en/rest/git).

It also bundles a full repository explorer, an offline-cached file tree
viewer, a multi-provider AI assistant, and a complete upload history log.

---

## ✨ Features

- **🗂️ Atomic folder / multi-file uploads** — stage a whole directory tree
  (or arbitrary files) and commit them to GitHub in a single commit using
  the Git Database API (blobs → tree → commit → ref update). No partial
  commits, no messy history.
- **📦 Repository browser** — list your repos, search public repos, bookmark
  favourites, and explore any repo's file tree with full offline Room
  caching.
- **👀 Code inspector** — open any file, decode base64 content, and get an
  AI-generated explanation of what the file does.
- **🤖 Multi-provider AI assistant**
  - Google Gemini (direct API key)
  - Gemini OAuth 2.0 (Bearer token)
  - OpenRouter (Claude, Llama, DeepSeek, …)
  - models.dev gateway
  - Self-hosted OpenCode endpoints
  - Any OpenAI-compatible API
  - Auto-generates Conventional-Commits-style commit messages from staged
    files, explains code, and answers general Git/Dev questions in chat.
- **🔐 Multi-account GitHub PAT management** — store several Personal Access
  Tokens and switch accounts instantly. Tokens are kept on-device only.
- **📜 Upload history** — every upload (success or failure) is logged with
  repo, branch, subfolder, file count, size, commit SHA and a link to the
  commit on GitHub.
- **🎨 Material 3 Expressive UI** — adaptive layout (phone + tablet), dark
  theme, customizable navigation rail, smooth animations.
- **♻️ Offline-friendly** — explored file trees are cached in a Room
  database so you can keep browsing when the network drops.

## 📐 Architecture

```
com.gitupload
├── MainActivity.kt                 # Single-activity Compose entry point
├── ui/
│   ├── MainViewModel.kt            # Central MVVM state holder
│   ├── screens/                    # Repositories, Upload, History, AI, Settings
│   ├── components/                 # Reusable Compose building blocks
│   └── theme/                      # Material 3 color, type & theme manager
├── data/
│   ├── api/                        # Retrofit GitHubApiService + client
│   ├── repository/                 # GitUploadRepository (upload engine)
│   ├── ai/                         # Multi-provider AI assistant manager
│   ├── scanner/                    # SAF folder & multi-file scanner
│   ├── db/                         # Room entities, DAOs, database
│   └── models/                     # GitHub + Git Database API DTOs
└── util/                           # GitHub webhook verifier
```

The **upload engine** (`GitUploadRepository.executeFolderUpload`) is the
heart of the app. For each upload it performs the classic 5-step Git
Database API dance:

1. `GET /repos/{owner}/{repo}/git/ref/heads/{branch}` → resolve HEAD SHA
2. `POST .../git/blobs` → create a blob per file (base64)
3. `POST .../git/trees` → build a tree referencing all blobs (base_tree = HEAD)
4. `POST .../git/commits` → create a commit with the new tree, parent = HEAD
5. `PATCH .../git/refs/heads/{branch}` → fast-forward the branch

If any step fails, the branch is left untouched — your repository is never
left in a half-uploaded state.

## 🚀 Getting started

### Prerequisites

- **Android Studio** (Ladybug or newer) with Android SDK 36
- **JDK 21** (bundled with recent Android Studio)
- A GitHub **Personal Access Token** (classic or fine-grained) with `repo`
  scope (and `workflow` if you want to push workflow files)

### Build locally

```bash
# 1. Clone
git clone https://github.com/marbou92/GitUpload.git
cd GitUpload

# 2. (Optional) provide your Gemini key for AI features at build time
cp .env.example .env
#   then edit .env:  GEMINI_API_KEY=your_real_key

# 3. Build & run
./gradlew assembleDebug          # debug APK
./gradlew installDebug           # install on a connected device
./gradlew testDebugUnitTest      # run unit tests
```

> The Gradle wrapper is included, so no local Gradle install is required.
> If the build complains about a Gradle/AGP version mismatch, regenerate
> the wrapper with `./gradlew wrapper --gradle-version <version>`.

### Run with Android Studio

Open the project folder, let Gradle sync finish, pick a device/emulator and
press ▶️ Run.

## ⚙️ Configuration

### `.env` (build-time secrets)

The [Secrets Gradle Plugin](https://github.com/google/secrets-gradle-plugin)
reads `.env` (gitignored) and `.env.example` (committed, with a placeholder)
and exposes the values as `BuildConfig` fields.

| Variable | Purpose |
|----------|---------|
| `GEMINI_API_KEY` | Default Gemini API key for AI features (can be overridden at runtime in-app) |

`.env` is **never** committed — see `.gitignore`.

### Firebase (optional)

The app can use Firebase Auth and App Check, but a `google-services.json`
is **not required** to build — the `google-services` plugin is configured
with `missingGoogleServicesStrategy = WARN`. Drop a real
`google-services.json` into the `app/` module only if you want Firebase at
runtime.

## 📦 CI / CD

Two GitHub Actions workflows are included in `.github/workflows/`:

### `ci.yml` — Continuous Integration
Runs on every push to `main` and on every pull request. It:
- sets up JDK 21 + Gradle,
- runs `testDebugUnitTest`,
- runs `lintDebug`,
- builds the debug APK,
- uploads the APK, lint reports, test results and screenshots as artifacts.

### `release.yml` — Release APK
Triggered by pushing a `v*` tag (or manually from the Actions tab). It:
- builds a **signed** release APK,
- uploads it as a workflow artifact,
- creates a **GitHub Release** with the APK attached.

#### Signing the release

For production releases, provide a stable upload keystore as repository
secrets (Settings → Secrets and variables → Actions):

| Secret | Value |
|--------|-------|
| `KEYSTORE_BASE64` | `base64 -i my-upload-key.jks \| tr -d '\n'` |
| `KEY_ALIAS` | key alias (default `upload`) |
| `STORE_PASSWORD` | keystore password |
| `KEY_PASSWORD` | key password |

Generate a keystore once:

```bash
keytool -genkeypair -v \
  -keystore my-upload-key.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass YOUR_STORE_PASS -keypass YOUR_KEY_PASS \
  -dname "CN=GitUpload, O=GitUpload, C=US"
```

If the secrets are **not** set, the workflow still builds a signed APK
using a freshly generated disposable keystore — handy for testing, but
**not** suitable for Play Console uploads (the signing key changes every
run).

#### Cut a release

```bash
git tag v1.0.0
git push origin v1.0.0
# → the Release APK workflow runs and publishes a GitHub Release
```

## 🔐 Security & privacy

- GitHub PATs are **encrypted at rest** with AES-GCM using a device-bound
  key held in the Android Keystore, then persisted in the local Room
  database. The Keystore key never leaves the device, so stored tokens
  cannot be decrypted on another device. The token database is also
  excluded from Auto Backup / device transfer. AI provider keys live in
  memory only. Secrets are never transmitted anywhere except directly to
  GitHub / your chosen AI provider.
- No telemetry, no analytics, no third-party trackers.
- `.env`, keystores and `google-services.json` are gitignored.
